# Use this repository with your AI assistant

Give the assistant access to this repository. The following is a setup/review brief, not permission to alter your accounts or install tools automatically.

> Read README.md and START-HERE.md. Identify my actual harness, version, authentication/billing route, provider and selected model without exposing credentials. Read the matching harness guide and the Conservative/Aggressive mode I select. If a route or feature is uncertain, verify current official documentation rather than guessing.
>
> Preserve my model, reasoning effort, native login, permissions, project instructions and required checks unless I explicitly approve a separate change. Do not install every listed component, overwrite configuration files, weaken tests, broker subscription credentials or replace native context state.
>
> Propose the smallest useful change for my real task. Fill the route passport, task contract and change receipt. Show the exact intended changes, expected mechanism, evidence limits, verification and rollback. Ask for approval before applying them.
>
> After approval, use only supported mechanisms. Verify effective settings and a complete task, including failures, retries and recovery. If something is unsupported, leave it unchanged and explain the narrower workable route. Do not describe a documentation check as an authenticated runtime test or a modeled saving as a measurement.
>
> Record what was changed, what was actually verified, what remains uncertain and how to undo it. Keep sensitive data outside this repository. Stop when the agreed criteria are satisfied or a genuine blocker remains; do not create an endless optimization loop.

## If the assistant starts building a platform

Redirect it: this is a blueprint and recipe repository. Use existing native capabilities and justified optional components. Do not invent a central controller, runtime, proxy or dashboard as a prerequisite.

## If the assistant promises a percentage

Ask for the denominator: selected tool output, whole-task tokens, billed API dollars or subscription allowance. Ask whether it is an external study, a modelled scenario or your own measured result. The [claims policy](docs/claims-policy.md) explains the distinction.

## If the assistant finds a new option

Compare it to the current native baseline and selected component. Check exact license, model/weight dependencies, account terms, restoration and hidden setting changes. Add it as an option only if it serves a real need; a longer list is not a better setup.
