# Contributing

Improve a real operator path, not the number of tools in a list.

1. Identify the task, harness/version, authentication/provider route and exact gap.
2. Use current first-party documentation or inspected source. Record check date and limits.
3. Give a small safe recipe, verification and rollback. Preserve model/effort/auth/permissions unless the change is separately explicit.
4. Update the route/market catalogue where relevant. Do not delete a required profile to make validation pass.
5. Run `python3 scripts/validate.py` and `python3 -m unittest discover -s tests -v`.
6. Separate documentation/fixture validation from an authenticated native task trial. Include redacted evidence only.

Do not submit credentials, customer records, private paths, real account traces or copied proprietary instructions. Add appropriate upstream notices for adaptations. See [claims policy](docs/claims-policy.md).

For a changed official interface, show the previous and current source and the affected recipe. For a savings claim, provide the actual workload denominator, baseline, failures, overhead and acceptance results. A percentage from another project is not a benchmark of this blueprint.

The repository remains a blueprint collection. A new installer, service, agent runtime or mandatory gateway is a separate scope decision, not an incidental documentation improvement.
