# Failure and edge-case playbook

Use the response below instead of repeatedly retrying a broken optimization. A recovery action must preserve permissions and current source state.

## Route and account failures

### The model name is right, but the bill is wrong

Inspect the effective native auth/provider path and non-secret override settings. Check the actual account receipt. Do not assume a logged-in subscription pays when an explicit API route is selected, or that exporting a key always overrides an active login. Follow the exact harness guide.

### A subscription reaches its limit

Record the unfinished task and actual reset/usage information. Wait through a supported process if the deadline allows, or request an explicitly approved alternative route. Do not pool other people's seats or silently lower model capability.

### A gateway returns text but loses tools or state

Verify native schema discovery, tool-call pairing, images/resources, cancellation and continuation. Restore the original supported endpoint if any required feature is lost. Do not strip unknown fields until the request happens to work.

### A hook exists but output replacement does not

Check the actual event/field contract. Passive logging, pre-input rewriting and post-output replacement are different capabilities. Do not call an ignored hook a successful optimization or use denial/retry loops as transparent compression.

### Headless auth waits for an interactive prompt

Use an officially supported noninteractive route already authorized for that environment. Do not embed a human refresh token or bypass the organization helper. Stop rather than hang indefinitely or switch billing silently.

## Evidence and task failures

### The user asked for every record or passage

Enumerate and reconcile the complete source set. Deterministic computation may process all rows outside the model; complete semantic review still requires reviewing every relevant passage. Sampling is not completion.

### An important exception disappears

Restore the exact passage plus neighbors, entity relationships and source context. Protect the implicated material for the remainder of the subgoal. A confidence score is not proof that other exceptions survived.

### A source changed after indexing

Invalidate affected views, summaries and reusable results. Recheck deletions, renames, corrections and downstream dependencies. Rebuild where dependency coverage is uncertain.

### An artifact reference expired or lost permission

Do not claim reversible compression. Use an authorized current source if available; otherwise report the missing criterion. Never restore revoked access from an old backup.

### The new question differs from the compressed one

Return to the originals and reconsider coverage. A diagnosis view is not a complete customer-impact list. Similar wording does not establish equivalent evidence needs.

### The code uses dynamic callers or generated configuration

Expand beyond the symbol map or first search result. Read relevant configuration, generated interfaces and tests. Do not infer completeness from an LSP navigation success.

### A compact format preserves values but the answer is wrong

Validate types, nulls, order, multiplicity and entity relationships. Compute exact aggregates in code. A codec roundtrip does not guarantee the model performs correct reasoning over it.

### A screenshot crop hides the critical detail

Restore full-frame context or higher-detail evidence as the task requires. Text-only extraction is not equivalent when layout, chart styling, spatial relationships or nonverbal audio matter.

## Cost and execution failures

### A smaller prompt costs more

Check cache invalidation, helpers, restores, extra turns and failed attempts. Revert the implicated method if complete-task value is negative. Do not report only the first request.

### Several reducers touch the same material

Identify the owner of the surface. Disable the new overlapping transform or select an explicitly evaluated combination. Do not multiply their marketing percentages.

### An unchanged check keeps invoking the model

Use an existing deterministic precheck if the job is eligible. Still wake reasoning for errors, ambiguity, relevant changes, time-based obligations and scheduled substantive review. A failed fetch is not no change.

### A cancelled or failed tool may have caused an external effect

Treat the effect as unknown until verified through the live target. Retry only through supported idempotency or a newly approved action. Do not replay a write to reconstruct output.

### Telemetry shows zero for an unknown price

Record unknown pricing/usage instead of free operation. Keep provider-reported tokens, local estimates, invoice charges and fixed subscription fees separate.

## Team and lifecycle failures

### Another operator already did the same work

Verify task/source/environment/authority equivalence before reusing it. A related prompt, shared URL or similar file is not sufficient. Do not duplicate writes or reuse someone else's approval.

### A plugin update or shared state changes another session

Revert only owned changes and pin a stable per-task policy. Recheck the active project, account and tool ordering. Avoid process-global mode or tenant state.

### Removing a tool also deletes history

Inspect the actual uninstall behavior, export/retain authorized evidence, and remove only owned integration state. Verify the native client and unrelated plugins afterward.

## When to stop

Stop with a useful checkpoint when a required criterion cannot be satisfied safely within the authorized route/budget. Do not turn incompleteness into a success message just because fewer tokens were used.
