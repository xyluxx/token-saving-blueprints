# Conservative blueprint

**Goal:** remove avoidable work while preserving the job you asked for. This is the starting mode, not a guarantee that a model will make no mistakes.

[Start here](../../START-HERE.md) · [Choose your harness](../harnesses/index.md) · [Aggressive](aggressive.md)

## Keep these fixed

Keep the selected model, reasoning effort, native login, provider path, permissions, required deliverables and project checks. Preserve current corrections, exact identifiers, amounts/units, dates, quotations, material exceptions, unresolved failures and source provenance.

Native compaction and caching may already be active. Keep them as baseline; do not count their existing benefit as a new saving.

## The recipe

### 1. State the coverage requirement

Use the [task contract](../../templates/task-contract.md).

- Exact lookup: retrieve the identified value and its source.
- Complete calculation: process every eligible record in code, reconcile counts and report results/exceptions.
- Complete semantic review: every required passage needs review. Search ranking cannot replace it.
- Exploration: start with selected evidence, label the limits and expand.
- External action: retain approval, current-state checks and exact readback.

### 2. Avoid model calls that do not add judgment

Use existing execution tools for pagination, joins, arithmetic, sorting, copying, formatting and artifact production. Reuse a verified script with current parameters instead of regenerating it.

For recurring checks, detect actual source changes before invoking a model. Distinguish a failed fetch from no change, and do not suppress time-based obligations or a scheduled substantive review. See [recurring work](../playbooks/recurring-work.md).

### 3. Read precisely, then expand when necessary

Start with exact paths, symbols, entity IDs and source fields. Use the harness's native search/navigation. Add Serena or another component only if it fills a verified gap.

A symbol map is orientation, not proof you inspected the affected implementation. Read callers, configuration, tests and dynamic paths when the task depends on them. For a request to read the whole file or review every record, do so.

### 4. Keep bulk results outside the conversational loop

Save complete authorized inputs and generated artifacts in a private task workspace. Return exact requested results, source references, counts and exceptions instead of reprinting everything between tools.

Prefer native bounded outputs and artifact spilling. Use an optional command-specific filter only if it preserves the complete original, errors, exit status and required interpretation. Upstream RTK recovery has bounds; verify them rather than assume every byte is retained. See [component selection](../component-selection.md).

### 5. Preserve meaning when changing representation

Compact JSON, typed CSV or a suitable reversible encoding may reduce repeated keys. Count the selected model's tokens when available, including added instructions and headers. Byte size alone is not enough.

Keep null versus missing, decimal precision, order, multiplicity and identity. Ten identical payments are not one payment. Do not re-encode signed data, API schemas, tool-call IDs, provider thinking or opaque compaction objects. Use deterministic calculations rather than asking the model to infer totals from a compact table.

### 6. Generate the smallest complete change

For coding, follow [coding and review](../playbooks/coding.md): inspect existing solutions, use the standard library/native platform where it meets the requirement, avoid speculative scaffolding, use precise patches and retain all required checks.

Ponytail is an optional influence on the coding method, not permission to ship less. This repository's [coding policy](../../templates/coding-policy.md) explicitly keeps scope and testing requirements.

For prose, avoid repeated preambles and restating source data, but do not impose a brevity ceiling that removes requested analysis.

### 7. Verify the complete result

Use the same acceptance criteria as the baseline. Record failed attempts, restores, extra calls and human repair. Retain a change only if it helps the actual task. A filter that saved input but caused extra troubleshooting may be a loss.

## Optional workers and API add-on

[Delegation](../delegation.md) can keep a bounded job in a smaller, complete worker context. The parent verifies the result. Cheaper/free worker models require a separate cost/quality choice; do not silently change the main model or effort.

The [OmniRoute add-on](../addons/omniroute.md) is a restricted API pilot, not a default gateway. Its narrow structured-data candidate needs the route, parsing, coverage and request-size gates. If those cannot be met, leave gateway compression off. Native subscription login stays on its supported native route by default. An already approved OAuth gateway or CLI-owned bridge can also use Conservative methods; creating or changing that route requires separate consent and provider-specific checks.

## Do not add these by default

- Generic summaries that replace native history.
- Statistical sampling for an exhaustive task.
- Token deletion from instructions, legal qualifications or active code.
- Lower effort, cheaper models or hidden account fallback.
- Semantic final-answer caching for current facts or actions.
- Multiple reducers competing for the same material.
- A proxy simply because it claims compatibility.

## Stop or revert when

A required value is missing, a count fails, a citation is unsupported, a source is stale, a tool format changes, the original cannot be recovered or the setup changes permissions/model/auth unexpectedly. Restore the original through supported native mechanisms. A permission failure blocks the action; it is not a reason to bypass security.

## What you can reasonably claim

You can describe the verified mechanism and the result of your own task trial. You cannot claim a universal average from this blueprint. Use [measurement](../measurement.md) and keep subscription capacity, API dollars and actual token reduction separate.
