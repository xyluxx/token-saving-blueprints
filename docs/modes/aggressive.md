# Aggressive blueprint

**Goal:** reduce eligible context further when the task permits a stated quality/recovery tradeoff. Keep the Conservative protections; do not force a fixed deletion ratio.

[Conservative](conservative.md) · [Choose your harness](../harnesses/index.md) · [Recovery cases](../edge-cases.md)

## Begin with the Conservative baseline

First avoid repeated calls, process data deterministically and use focused native tools. Aggressive is not a substitute for fixing waste at its source. If the change is only exact native retrieval or complete computation, it may already be Conservative. Choose Aggressive when deliberately introducing selective or lossy context with recovery.

Keep the main model, effort, native auth, permissions and required scope unchanged. Alternative models, lower effort or a different billing route require separate consent under [cost choices](../auth-and-billing.md). Optional compressor models also need explicit provisioning and overhead accounting.

## Use this mode for eligible work

Good starting candidates are repository exploration, repetitive logs, background document synthesis and long tasks with completed subgoals. Keep decision-critical financial/legal/security material exact. Complete-record and complete-semantic-review requests still require full coverage.

Do not use it merely because the conversation is long. A short passage may contain the decisive exception; an old error can still be unresolved.

## The recipe

### 1. Protect the active task state

Use a private [working set](../../templates/working-set.md) containing the latest request/corrections, acceptance criteria, approved and forbidden actions, current source versions, unresolved errors, decisions with evidence and artifact locations.

Verify this state against sources. A model-written summary is not an authoritative record simply because it has headings. Keep permission grants separate from historical action receipts.

### 2. Reduce fresh observations first

Use exact task-relevant sections, goal-aware code selection or a supported reduced tool view. Keep headings, qualifiers, relationships, failure context and source locations.

Choose one transformation owner. If a native tool or an existing plugin already reduced the block, do not independently shrink it again. Rebuild from the original when a different view is needed.

For code discovery, a goal-aware skimmer such as SWE-Pruner is an experimental option, not a default for active edits. Its coding-agent results do not establish code-completion fidelity. Read the relevant full implementation before consequential changes. See [evidence](../evidence.md).

### 3. Reduce history only through a supported seam

At a completed subgoal or genuine context-pressure point, consider a native checkpoint/compaction operation or a documented context-management extension for the exact harness.

Retain the recent meaningful working set and unresolved evidence. Replace eligible obsolete observations with source-linked notes or references. Do not copy a universal “last ten messages” policy between tools: their turns and internal state differ.

If the harness has no supported history surface, do not edit its session database or opaque provider state. Use fresh-observation reduction and explicit source notes instead. The [harness guide](../harnesses/index.md) is the authority for that route.

### 4. Select one semantic method

Compare a simple exact-span approach before a learned or generative compressor:

- Background prose: question-aware passage/section selection.
- Old completed phases: structured checkpoint summary with source references.
- Code discovery: goal-conditioned selection outside the active edit target.
- Exploratory data: representative sampling only when the requested output explicitly permits it.

A question change invalidates a question-specific view. A summary for outage diagnosis is not complete evidence for listing every affected customer.

LLMLingua, Headroom learned paths and similar options are alternatives to evaluate, not layers to stack. Check code/weight licenses, local or external processing, latency, token overhead and restoration. Do not assume an extra model is free.

### 5. Protect the native cache and protocol

Prefer a stable prompt prefix and observations that remain unchanged after their first submission. Rewriting a warm history can add cache writes, helper work and retries. A smaller request may still cost more.

Preserve native tool pairing, structured content, signatures, images/resources, continuation identifiers and encrypted compaction state. Do not flatten everything into generic chat to make a proxy accept it.

### 6. Restore based on evidence, not confidence alone

Escalate when a required entity/value is absent, totals/pagination do not reconcile, citations lack support, contradictions remain, an action targets unexpected state or the agent keeps refetching.

Restore in order:

1. Exact source span and relevant neighbors.
2. Wider source/candidate set.
3. Full relevant observation or document.
4. Conservative operation for the affected workstream.
5. A supported native reset/resume from a verified checkpoint, if necessary.

Do not replay writes, copy approvals to a different action, or patch provider state to simulate restoration. If the original is expired, inaccessible or too large for a safe route, report the incomplete criterion. See [edge cases](../edge-cases.md).

### 7. Compare the full task

Use [the paired trial](../measurement.md). Include compressor/helper use, cache churn, restores, retries and final verification. Check hard task strata as well as the average. Do not count a smaller first prompt as the final saving.

## Optional delegation and OmniRoute

Use [delegation](../delegation.md) with explicit worker scope, model/effort, permissions and verification. A cheaper worker is a separate economic option, not another compression percentage.

The [OmniRoute profile](../addons/omniroute.md) selects one eligible output owner after its protocol, provider-policy, account and runtime gates pass, whether the approved upstream authenticates with a key or OAuth. It does not mean turning on the gateway’s `aggressive` or every registered engine. [Free-provider lanes](../addons/free-provider-lanes.md) have their own entitlement, spending and privacy checks.

## Optional later methods

Only after simpler methods are useful: task-specific media detail/crops, validated transcripts for word-only tasks, narrow calibrated semantic answer caching for static low-risk questions, and bounded recursive processing of very large corpora.

These methods cannot replace spatial/audio meaning, current-state checks, exact quotations or exhaustive review. Do not lower reasoning just because the previous event was a tool response.

## What this mode does not promise

No universal 75% average, 95% whole-task reduction or identical-quality guarantee. Published studies include gains and regressions. The useful promise is a documented method, preserved critical boundaries, a real recovery path and a transparent local decision about whether the change is worth keeping.
