# Delegation packet

Fill privately for one bounded worker. This is a planning template, not native configuration or a permission grant.

- Parent task and accountable owner:
- Exact worker question and complete acceptance criteria:
- Why a worker is useful instead of deterministic code or the existing main context:
- Source versions, freshness and permitted data:
- Complete-record/complete-passage requirement, if any:
- Worker kind: native subagent / alternate API model / headless harness / analysis-only API call:
- Execution host and how its lifecycle is supervised:
- Main model and effort to preserve:
- Approved worker model/provider, actual billing account/project and supported effort:
- Allowed fallback set; empty means stop:
- How disallowed fallback is prevented before the call:
- Tool/source permissions and write scope; do not include secrets:
- Explicit external actions allowed, with current authorization checked separately:
- Request/time/concurrency and spending limits; what really enforces them:
- Output format, source citations, artifact locations and exception reporting:
- Actual resolved worker model/effort and all attempts:
- Main-agent verification and escalation condition:
- In-flight action reconciliation, cancellation and handoff:

Do not forward the parent's entire memory, another client's data or reusable approval tokens. If the runtime cannot honor the required controls, choose a supported route or stop instead of guessing a field.
