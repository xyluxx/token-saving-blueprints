# Cross-harness handoff

Use a shared record only when every recipient is authorized for its sources. Do not paste private task data into this repository.

- Task identity, owner and acceptance criteria:
- Source/branch/worktree/environment versions:
- Current model/auth constraints and destination harness:
- Completed criteria with evidence:
- Files/artifacts produced and how to access originals:
- Tests actually run and unresolved failures:
- Latest corrections and obsolete conclusions:
- Remaining work and exact next action:
- Current permissions to recheck:
- Irreversible effects already performed:
- Known destination capability gaps:

Before resuming, verify current access, source revisions and supported tool/state behavior. A handoff does not transfer subscription credentials, native tool IDs, encrypted reasoning or approval tokens. A recipient should not start a duplicate execution while the original owner is still performing the same task.
